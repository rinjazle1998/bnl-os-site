Overview

BNL-OS Documentation

BNL-OS is a custom embedded Linux distribution built entirely with the Yocto Project (Scarthgap / 5.0). It is designed for constrained hardware targets where image size, boot time, and security posture matter.

This documentation covers everything from setting up a build environment to deploying OTA updates on target hardware.

ℹ️ BNL-OS currently targets ARMv7 and AArch64 platforms. x86-64 support is experimental.

Requirements

Before building BNL-OS you need the following on your host machine:

Host OS

A 64-bit Linux host is required. The following distributions are tested and supported:

  • Ubuntu 22.04 LTS or 24.04 LTS (recommended)
  • Debian 12 (Bookworm)
  • Fedora 39+

Hardware

  • At least 8 GB RAM (16 GB recommended)
  • At least 100 GB free disk space
  • Multi-core CPU (build times scale linearly with core count)

Software

# Ubuntu / Debian
sudo apt update && sudo apt install \
  git wget curl python3 python3-pip \
  gawk make gcc g++ diffstat texinfo \
  chrpath socat libsdl1.2-dev pylint \
  xterm liblz4-tool zstd

Quickstart

The fastest way to get a working BNL-OS image running.

1. Clone the repository

git clone https://github.com/YOUR_USERNAME/bnl-os.git
cd bnl-os

2. Initialise the build environment

source oe-init-build-env build

3. Build the full image

bitbake bnl-image-full
💡 Initial builds take 2–4 hours depending on your CPU. Subsequent builds are incremental and much faster thanks to Yocto's shared-state cache.

4. Find your image

# Output images are in:
build/tmp/deploy/images/MACHINE/bnl-image-full-MACHINE.wic.gz

Build setup

BNL-OS uses a kas configuration file for reproducible layer management. This is the recommended approach over manually editing bblayers.conf. 

# Install kas
pip3 install kas

# Build using kas (handles layer cloning automatically)
kas build kas/bnl-os.yml

Layers

BNL-OS is composed of the following Yocto layers:

LAYER PURPOSE
meta-bnl BNL-OS distro policy, image recipes, and custom configurations
meta-bnl-bsp Board Support Packages for supported hardware targets
meta-openembedded Extended OpenEmbedded package collection
poky Yocto Project reference distro (upstream)

BSP Guide

The meta-bnl-bsp layer contains machine configurations for supported hardware targets. To add a new machine, create a .conf file under meta-bnl-bsp/conf/machine/. 

# meta-bnl-bsp/conf/machine/bnl-rpi4.conf
require conf/machine/include/rpi-base.inc

MACHINE_FEATURES += "wifi bluetooth"
KERNEL_DEVICETREE  = "broadcom/bcm2711-rpi-4-b.dtb"
UBOOT_MACHINE      = "rpi_4_defconfig"
PREFERRED_PROVIDER_virtual/kernel = "linux-bnl"

local.conf

Key variables to set in build/conf/local.conf:

# Target machine
MACHINE = "bnl-rpi4"

# Parallel build threads (set to your CPU core count)
BB_NUMBER_THREADS = "8"
PARALLEL_MAKE    = "-j8"

# Shared state and download directories (speeds up rebuilds)
SSTATE_DIR  = "/opt/yocto/sstate-cache"
DL_DIR      = "/opt/yocto/downloads"

# Enable read-only rootfs
EXTRA_IMAGE_FEATURES += "read-only-rootfs"

Image targets

BNL-OS provides three image targets:

  • bnl-image-minimal — kernel + init + busybox only
  • bnl-image-full — recommended; includes networking, dropbear SSH, and base utilities
  • bnl-image-dev — full image plus development tools (gcc, gdb, strace)

Flashing

See the Download page for detailed flashing instructions using bmaptool and dd.

OTA updates

BNL-OS uses an A/B (dual-bank) partition layout. At runtime, one bank is active while the other is available for updates. After a successful update, the bootloader flips the active bank. If the new bank fails to boot three times, it automatically reverts to the previous good bank.

Trigger an OTA update manually

# Check current active slot
bnl-update --status

# Apply an update bundle
bnl-update --apply /path/to/bnl-os-1.1.0.swu

# Reboot to activate
reboot
💡 Update bundles (.swu) are generated by the bnl-image-update BitBake target and are signed with a device-specific key.
