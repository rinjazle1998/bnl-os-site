How to install — when the release is available

The steps below show exactly how to download and flash BNL-OS to your hardware. This guide is ready so you can prepare in advance.

1

Download the image from GitHub Releases

When released, all images will be on the GitHub Releases page of this project. Two variants will be available:

  • Full image Recommended for most users — kernel + rootfs + bootloader, ready to flash.
  • Minimal image For advanced deployment scenarios requiring minimal footprint.
2

Verify the checksum (important)

Every release ships with a SHA256SUMS file. Always verify before flashing — this ensures the image was not corrupted during download. 

# Download the checksums file alongside the image
wget https://github.com/rinjazle1998/bnl-os-site/releases/latest/download/SHA256SUMS

# Verify — should print "OK"
sha256sum --check SHA256SUMS --ignore-missing
3

Flash the image to your storage device

Identify your SD card or eMMC device with lsblk, then choose your flashing method:

# Install bmaptool
sudo apt install bmap-tools

# Flash — replace /dev/sdX with your actual device
sudo bmaptool copy bnl-os-1.0.0-full.wic.gz /dev/sdX

bmaptool is faster than dd because it skips empty blocks. Install it with apt on Ubuntu/Debian. 

# Decompress and flash in one command
gunzip -c bnl-os-1.0.0-full.wic.gz \
  | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
⚠️ Run lsblk first to confirm your device path. Writing to the wrong device is irreversible.

On Windows, use Rufus or balenaEtcher:

1. Download and open Rufus or balenaEtcher
2. Select your SD card / USB device as the target
3. Select the .wic.gz image file as the source
4. Click Flash / Write and wait for it to finish
ℹ️ Both Rufus and balenaEtcher can directly flash .wic.gz files without decompressing first.
4

Insert into target hardware and power on

Insert the SD card or eMMC into your target board, apply power, and BNL-OS will boot automatically. Default serial console is on ttyS0 at 115200 8N1.

💡 First boot may take slightly longer as the system initialises the filesystem overlay. Subsequent boots will be faster.
